# lokerpc

HTTP JSON-RPC framework for LOKE services. Handles routing, schema generation, TypeScript codegen, and Prometheus metrics.

## Defining a service

```go
svc := lokerpc.NewService("payments", "Payment service.", lokerpc.EndpointCodecMap{
    "queryPayments": lokerpc.MakeStandardEndpointCodec(svc.QueryPayments, "Query payments"),
    "createPayment": lokerpc.MakeStandardEndpointCodec(svc.CreatePayment, "Create a payment"),
})

lokerpc.MountHandlers(logger, mux, svc)
```

This mounts:
- `POST /rpc/payments/<method>` — RPC endpoints
- `GET  /rpc/payments` — service metadata (JTD schema + method list)
- `GET  /rpc`          — root metadata (all services)

## TypeScript codegen

The metadata endpoint drives TypeScript client generation. Godoc comments on your request/response structs become JSDoc in the generated TypeScript.

### How it works

1. At startup, `MountHandlers` calls `EnrichWithDocs` for each service.
2. `EnrichWithDocs` looks for struct and field documentation in two places (in priority order):
   - **Registered docs** — pre-extracted at build time via `go generate` (works in production)
   - **Runtime AST** — parsed from source files on disk (works in development, fails in production containers)
3. Descriptions are attached as `metadata.description` on JTD schemas and rendered as `/** JSDoc */` by the codegen tool.

### Setting up `go generate` (recommended for production)

Add a single line to any file in each service package — a dedicated `generate.go` is a clean convention:

```go
//go:generate go run github.com/LOKE/pkg/lokerpc/cmd/gendocs -src . -out rpc_docs_gen.go
package payments
```

Run generation before building:

```bash
go generate ./pkg/payments/...
go build ./cmd/api
```

Or add it to your Makefile:

```makefile
.PHONY: generate
generate:
	go generate ./pkg/payments/... ./pkg/credit/... # add each service package

.PHONY: build
build: generate
	go build ./cmd/api
```

The tool writes `rpc_docs_gen.go` alongside your source. You can either commit it (regenerate when types change) or gitignore it (regenerate on every build — same pattern as protobuf).

### What gets generated

```go
// Code generated by lokerpc/cmd/gendocs. DO NOT EDIT.

package payments

import lokerpc "github.com/LOKE/pkg/lokerpc"

func init() {
    lokerpc.RegisterTypeDocs("github.com/LOKE/aston-api/pkg/payments", map[string]lokerpc.TypeDocEntry{
        "QueryPaymentsRequest": {
            Doc: "QueryPaymentsRequest is the service-layer request for listing payments.",
            Fields: map[string]string{
                "organizationUid": "OrganizationUID scopes results to a single organisation.",
                "skip":            "Skip is the number of rows to skip for pagination.",
            },
        },
    })
}
```

`RegisterTypeDocs` is called in `init()` so docs are available before the first request, with no file I/O at runtime.

### Development without `go generate`

In development, if `rpc_docs_gen.go` is absent (e.g. gitignored and not yet generated), `EnrichWithDocs` falls back to parsing source files from disk automatically. No extra setup needed — run your server and docs appear. Production builds should always have the generated file to avoid the runtime dependency on source files.

### gendocs flags

| Flag | Default | Description |
|------|---------|-------------|
| `-src` | `.` | Source directory to scan |
| `-out` | _(required)_ | Output file path |
| `-pkg` | _(auto)_ | Override package import path (detected from `go.mod`) |

## Enum support

Enums are registered separately via `RegisterEnumValues` and detected from `validate:"oneof=..."` tags. See `schema.go` for details.
